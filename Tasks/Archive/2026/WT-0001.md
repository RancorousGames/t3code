## Description

Jacob cannot see which keep-awake scheduled actions are active in OmniHub or T3 Code. Add an easily accessible window in T3 Code that shows the live OmniHub keep-awake monitors, including ones awaiting a final wake after their requested duration. Show target session title/link, current status, interval, end time, next attempt, last wake/result and a plain-language reason when delivery cannot proceed. Make active/retrying actions easy to find; distinguish finished/cancelled history. Keep T3 scheduled tasks and OmniHub monitors clearly identified by their actual source. Use the existing scheduler as the source of truth; this task is visibility, not a new scheduler or scheduler migration.

Both had recent scheduler ticks but neither was sending at inspection time.

Implementation reference: OmniHub Tools owns the existing scheduler in Omnish/main/src-omnihub-tauri/src/mcp_keep_awake_temp.rs; persisted state is %LOCALAPPDATA%/OmniHub/temporary-keep-awake-v1.json. Existing T3 UI components include ScheduledTasksSettings.tsx and ThreadAutomationsPanel.tsx.

## Acceptance Criteria

- [ ] A discoverable T3 window lists current OmniHub keep-awake monitors and updates their status without reopening the app.
- [ ] Each active item identifies its target, interval, end time, next retry and most recent delivery outcome; missing sessions and unresolved delivery are explained clearly.
- [ ] Overdue final-wake retries remain visible as active/pending; finished or cancelled items are distinguishable.
- [ ] Opening or refreshing the window does not create, send, cancel or otherwise mutate keep-awake actions.
